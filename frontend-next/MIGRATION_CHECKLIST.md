# frontend-next Migration Checklist

> Status values: `Not Started`, `In Progress`, `Ported`, `Verified`, `Blocked`.
>
> `Verified` means UI is displayed, user event works, real existing backend API is called, request schema is identical, response renders, error state is handled, and behavior matches the Vanilla app. Component existence alone is not enough.

## Repository analysis

### Existing structure

- `frontend/`: current Vanilla JavaScript app served by FastAPI/Docker as static files.
  - Entrypoint: `frontend/index.html`.
  - Styles: `frontend/css/style.css`.
  - Scripts loaded by HTML: `api.js`, `map.js`, `business_picker.js`, `tabs.js`, `watchlist.js`, `site_score.js`, `dashboard.js`, `candidate_compare.js`, `simulation.js`, `lease_analysis.js`, `app.js`.
- `frontend-react/`: Vite React shell, not a completed feature port.
  - Entrypoint: `frontend-react/src/main.tsx` -> `App.tsx`.
  - Reusable assets: `src/design-system/tokens.css`, `src/styles/app.css`, `src/components/map/KakaoMap.tsx`, `src/lib/kakao.ts`, `src/lib/api.ts`.
  - Current limitation: contains map/design shell only; dashboard/cannibalization/territory/synergy/lease/simulation/watchlist/compare are not fully implemented.
- `frontend-next/`: new Next.js App Router TypeScript app created for this migration.
- `backend/`: FastAPI backend.
  - Entrypoint: `backend/app/main.py`.
  - Docker backend port: `8000`.
  - Existing static serving uses `frontend/` via `docker-compose.yml` volume `./frontend:/app/static:ro`.

### Build and run commands

- Backend: `uvicorn app.main:app --reload --port 8000` from `backend/`, or Docker compose from repo root.
- Existing Vanilla frontend: served by backend at `http://localhost:8000`.
- Existing React shell: `cd frontend-react && npm run dev`.
- New Next.js app: `cd frontend-next && npm run dev` (port 3000).

### Environment variables

- Backend: `.env` / Docker env includes `KAKAO_REST_KEY`, `DATA_GO_API_KEY`, `DATA_SEOUL_GO_API_KEY`, `SGIS_*`, `OPENAI_API_KEY`, etc.
- Vanilla frontend hardcodes Kakao JS key in `frontend/index.html` today.
- React shell uses `VITE_KAKAO_JS_KEY`.
- Next app uses:
  - `NEXT_PUBLIC_API_BASE_URL=` (empty uses the same-origin Next proxy)
  - `BACKEND_API_BASE_URL=http://localhost:8000`
  - `NEXT_PUBLIC_KAKAO_JS_KEY=...`

### Global state in Vanilla app

Observed global/shared browser state includes:

- `window.__analyzeLocation`
- `window.__selectedUpjong`
- `window.__lastAnalyzedLocation`
- map instances/overlay arrays in `map.js`, `dashboard.js`, `simulation.js`
- watchlist state in `localStorage`
- active app tab state in `tabs.js`

Next.js migration should replace this with React state/context module by module while preserving payload schemas.
