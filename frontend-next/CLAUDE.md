# frontend-next 작업 규칙

Space Syntax 상권 분석 웹앱의 프론트엔드(Next.js 15 + React 19). 4개 탭(입지 분석 · 투자 수익성 · 신설도로 시뮬레이션 · 관심목록·후보지 비교)으로 구성.

## 디자인 규칙

- **기존 컴포넌트와 디자인 토큰을 우선 재사용한다.** 색·spacing·radius·타이포는 `styles/tokens.css`의 CSS 변수(`var(--blue-50)`, `var(--space-4)`, `var(--radius-md)` 등)를 쓰고, 공유 프리미티브(`.card`, `.primary-button`, `.status-banner`, `.score-bar`, `.text-input` 등)를 재사용한다. 새 하드코딩 색상·중복 컴포넌트를 만들지 않는다.
- **모바일과 데스크톱을 모두 확인한다.** 최소 390px(모바일)와 1440px(데스크톱)에서 레이아웃을 검증한다.
- **네온·과도한 그라데이션·불필요한 카드 추가를 피한다.** 시각적 위계와 여백으로 정보를 정리하되 장식을 위한 장식을 넣지 않는다.

## 검증 규칙

- **변경 후 실행 명령, 테스트, 스크린샷으로 검증한다.**
  - 타입: `npm run typecheck`
  - 테스트: `npm test`
  - 실행/스크린샷: dev 서버(`npm run dev`, 포트 3000)를 띄우고 브라우저에서 핵심 사용자 행동과 로딩·성공·실패 상태, 콘솔 오류를 확인한 뒤 전/후 스크린샷을 남긴다.
  - 실제 검증이 끝나기 전에는 완료라고 하지 않는다.
- 브라우저 검증에는 FastAPI 백엔드(`http://localhost:8000`)와 `http://localhost:3000`용으로 등록된 Kakao JS 키가 필요하다.
