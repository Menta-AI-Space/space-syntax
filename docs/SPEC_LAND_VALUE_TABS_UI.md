# 토지가치분석을 탭형 제품 화면으로 낸다 — 분석 종류 분기 + 6탭 결과

> ⚠️ **2026-09-25: 「뜰 자리」도 제품 결론이 아니다.** 검증(§15·§24)에서 미래 성장률과의
> 상관이 0이라 내렸다. 제품 결론은 **「구조가 받쳐 주는 자리」+「이미 늦은 자리 경고」**이고
> MVP는 상권 현재 분석 + 도면 분석 두 모듈이다. 근거는 `DECISIONS_LAND_MODEL.md` §26.
> 아래 본문의 「뜰 자리·오를 확률·유망입지·미래전망」은 **연구 트랙의 말**이지 화면 문구가 아니다.
>
> ⚠️ **2026-08-26 이후 이 문서의 「저평가」는 제품 결론이 아니다.**
> 제품은 **B(뜰 자리 — 같은 계층 대비 초과상승 확률)** 단일 결론으로 간다. 저평가 계산은
> 유지하되 갭 지표는 **뜰 자리 모델의 입력 feature**로만 쓴다(반증 불가 + 감정평가법상
> 위험). 근거는 `docs/DECISIONS_LAND_MODEL.md` §10.
> 아래 본문에서 「저평가·고평가」가 **사용자 화면의 결론**으로 나오는 대목은 전부
> 「뜰 자리(오를 확률)」로 읽는다. 화면에 "싸다"로 나가면 안 되고 "오를 확률이 높다"로
> 나가야 한다. 내부 계산·통제 방법을 설명하는 대목은 그대로 유효하다.


**상태 (2026-09-25): MVP에서 보류.** 토지가치 6탭은 결론(뜰 자리)이 검증에 걸려 실데이터에
붙이지 않고, 외주 범위에서도 뺀다(§26). 화면 구조 기록으로만 남긴다.

**이전 상태: 화면 구조는 데모로 확정, 모델·데이터 미결은 그대로.** 소유자 구술(2026-08-24)을
옮긴 문서다. 그 뒤 탭 구성·순서·문구는 `/demo` 라우트에 실제로 돌아가는 화면으로 서 있고,
데모는 토지가치 6탭에서 그치지 않고 **상권분석 6탭과 AI 후속 질문 장면**까지 담는다
(아래 「구현 상태」). 반면 아래 「미결」 절의 **Q1~Q7은 아직 답이 없다** — 데모는 그 답을
낸 것이 아니라 숫자가 예시임을 화면이 스스로 밝히는 방식으로 비켜 간 것이다. 모델·데이터·
표기가 확정되기 전에는 이 화면을 실데이터에 붙이지 않는다.

이 문서는 `docs/SPEC_PARCEL_LAND_VALUE_UI.md`의 **화면 결정을 뒤집는다.** 무엇을
뒤집는지는 아래 「뒤집는 결정」에 따로 모았다 — 뒤집는 줄 모르고 뒤집으면
같은 논쟁을 세 달 뒤에 다시 한다.

## Problem Statement

토지가치 판정이 **대화 안에 갇혀 있다.** 지금 필지를 누르면 판정이
`AgentChat` 스레드에 카드 한 장으로 들어가고([app/land/page.tsx](../frontend-next/app/land/page.tsx)),
그 카드 한 장에 판정·비교군·과거 흐름·미래 전망이 전부 쌓인다
([LandAnalysisCard.tsx](../frontend-next/components/parcels/LandAnalysisCard.tsx)).

그래서 두 가지가 안 된다:

1. **제품이 스스로 완결되지 않는다.** 사용자가 먼저 질문을 지어내야 분석
   결과에 도달한다. 무엇을 물어야 하는지 모르는 사람은 아무것도 못 본다.
2. **깊이를 담을 자리가 없다.** SHAP 요인·유사필지 목록·도시계획 항목을 한
   카드에 더 쌓으면 읽히지 않는다.

**AI는 분석의 입구가 아니라 후속 설명 창구여야 한다.** "왜 저평가야?" "이 주변
개발계획만 설명해줘"는 결과를 이미 본 사람이 하는 질문이다.

## Solution

### 1. 분석 흐름을 종류로 분기한다

```
분석지역 선택
   ↓
분석 종류 선택
   ├─ 토지가치분석 ──→ [분석 실행]          (추가 입력 없음)
   └─ 상권분석 ──→ 업종 선택 ──→ [분석 실행]
```

원칙: **해당 분석에 필요한 최소 입력만 받는다.** 토지가치분석의 종속변수는
필지이고 업종이 들어갈 자리가 없다. 지금은 업종을 먼저 묻고 있어서 토지만
보려는 사용자가 쓰지 않는 입력을 채우고 있다.

### 2. 결과는 상단 Summary + 탭이다

상단 Summary는 들어온 즉시 읽는 결론이고, 탭은 그 결론의 근거다.

```
토지가치 종합분석
  현재 개별공시지가      1,020만원/㎡
  모델 예측 공시지가     1,180만원/㎡
  Gap                   +15.7%
  향후 3년 예상 상승률   +18.2%
  유망입지 Percentile    상위 8%
  종합 판정             뜰 자리 후보 · 초과상승 확률 상위
```

**최종 탭 6개** (초안에서 7개로 나눴다가 줄였다 — 많으면 복잡하다):

| 탭 | 답하는 질문 |
| --- | --- |
| **종합** | 나머지 다섯 탭의 요약 + [상세보기] |
| **미래전망** | 앞으로 값이 어떻게 될 가능성이 있는가 (방법론 A) |
| **가치평가** | 지금 이 땅은 같은 조건 대비 낮은가 높은가 (방법론 C) |
| **유망입지** | 이 자리가 주변보다 더 오를 자리인가 (방법론 B) |
| **입지·도시계획** | 왜 그런가 — 공간 구조와 계획 (Layer B + 도시계획) |
| **주변비교** | 비교 대상은 무엇인가 (Comparable) |

`데이터·모델 근거`는 7번째 탭으로 두되 **기본 화면에서 감춘다**(전문 사용자용).

**「가치평가」와 「미래전망」의 자리를 맞바꿨다 — 소유자 결정(2026-08-24).** 초안에서는
가치평가가 종합 다음이었다.

**default 탭은 「미래전망」이다.** 「종합」이 첫 화면이 아니다 — 소유자 결정.
Summary가 이미 상단에 있으므로 종합 탭이 default면 같은 요약을 두 번 읽는다.

### 3. 탭 내용

#### 미래전망 (default)

```
현재     1,020만원/㎡
1년      1,080만원/㎡   +5.9%
3년      1,205만원/㎡   +18.1%
5년      1,340만원/㎡   +31.4%
```

꺾은선 하나(2026·2027·2029·2031)와, **왜 오를 것으로 보는지**를 글로:
교통 접근성 · 주변 상권 성장 · 도시계획 · 인구 변화 · 가격 추세 · 공간 네트워크 구조.

#### 가치평가

```
실제 개별공시지가   ₩10.2M/㎡      모델 예측 공시지가   ₩11.8M/㎡
Gap  +15.7%  → 뜰 자리 모델 입력 (화면 결론 아님)
```

아래에 **요인** — SHAP을 사람이 읽는 말로:

```
+ 지하철 접근성 ↑     + 상업시설 밀도 ↑     + 도로 네트워크 접근성 ↑     + Integration ↑
- 부정형 필지 ↓       - 도로접면 조건 ↓
```

#### 유망입지

가격 수준이 아니라 **주변보다 더 성장할 가능성**이다. 미래전망 탭과 분리한다.

```
유망입지 Score 87/100 · 해당 권역 상위 8%

향후 3년 예상 상승률     +18%
유사 필지 예상 상승률    +8%
─────────────────────────
예상 초과성장            +10%p
```

요인: 교통 접근성 상위 7% · 상권 성장 상위 13% · POI 증가 상위 9% ·
Space Syntax 상위 6% · 개발계획 영향 긍정적.

#### 입지·도시계획

Space Syntax를 **전용 탭으로 만들지 않는다** — 공간 데이터 묶음의 하나로 둔다.

```
Integration 상위 6%     Choice 상위 12%
지하철 180m             버스정류장 300m 내 8개      간선도로 우수
POI 밀도 상위 15%       생활인구 상위 21%
```

지도에 필지·주변 도로망·역·주요 POI·Integration Heatmap을 겹쳐 본다.

도시계획 쪽은 나열이 아니라 **가치 영향(긍정/중립/부정)**을 함께 붙인다:

```
용도지역 제2종일반주거    중립
지구단위계획 ○○지구      + 긍정적
신설역 계획 740m          ++ 매우 긍정적
높이제한                  - 부정적
정비사업 500m 내 ○○      + 긍정적
```

#### 주변비교

```
대상 필지        1,020만원/㎡
유사필지 A       1,150만원      B  1,190만원      C  1,125만원
유사필지 Median  1,155만원
```

지도에 비교 필지를 함께 띄우고, 각각의 거리·용도지역·면적·도로조건·공시지가·
모델 유사도를 낸다. **"왜 저평가라는데?"에 대한 신뢰가 여기서 올라간다.**

#### 데이터·모델 근거 (감춤)

사용 데이터 기준일 · 공시지가 연도 · 모델과 버전 · 검증 MAE · 사용 feature ·
누락 데이터. 그리고 반드시:

> 이 분석의 저평가·고평가는 실거래 시장가격 대비 평가가 아니라 **모델 예측
> 공시지가와 실제 개별공시지가의 차이**입니다.

모르면 안 되므로 여기서 한 번에 갈라 둔다. contract(`StructuredAnalysis`)는
이미 대부분 있고, **비어 있는 것은 모델과 원천 데이터다.**

## 구현 상태 — 데모는 이미 서 있다

이 문서는 처음에 "미결에 답이 나오기 전에는 구현하지 않는다"고 적었다. **그 사이에
데모가 만들어졌다.** 문서가 그 불일치를 감추면 다음 사람이 없는 줄 알고 다시 만든다.
아래는 2026-08-24 기준 저장소의 사실이다.

**이 데모는 Q1~Q7에 답한 결과가 아니다.** 데모가 통과시킨 명제는 하나뿐이다 —
*숫자가 예시임을 화면이 스스로 밝히면, 모델이 없어도 화면 배치는 미리 세워 볼 수 있다.*
Gap을 주력 판정으로 낼지(Q1), 예측을 점으로 낼지 구간으로 낼지(Q2), 화면 문구를 무엇으로
확정할지(Q3), 「가치 영향」의 근거를 무엇으로 삼을지(Q4)는 **여전히 미결이다.** 데모가 그
자리에 넣어 둔 것은 답이 아니라 자리표시다.

### 제품 화면은 `/land`다 — 데모와 코드를 공유하지 않는다

`/demo`는 **발표 자산이라 손대지 않는다**(소유자 결정 2026-08-24). 대신 같은 배치를
제품 쪽에 따로 세웠다. import도 CSS도 공유하지 않는다 — 한 벌로 묶으면 "숫자가 고정돼야
한다"(데모)와 "없는 값은 비워야 한다"(제품)가 서로를 망가뜨린다.

| 파일 | 무엇 |
| --- | --- |
| `frontend-next/app/land/page.tsx` | 「분석 결과」·「대화」 두 탭 + 오른쪽 지도 |
| `frontend-next/components/landvalue/LandValueResult.tsx` | Summary + 6탭. `StructuredAnalysis` 하나만 본다 |
| `frontend-next/lib/landValueTabs.ts` | 탭별 데이터 유무·비어 있는 이유·default 탭·표기 함수 |

… 이 화면의 수치는 예시 데이터입니다."

### 셋업 흐름이 코드에 들어간 방식

위 「1. 분석 흐름을 종류로 분기한다」가 그대로 `Setup` 컴포넌트다. 분기는 로직이 아니라
데이터에 들어 있다 — `ANALYSIS_KINDS`의 `needsIndustry`가 `land: false` / `trade: true`
이고, 업종 단계는 그 값이 참일 때만 렌더된다. 그래서 토지가치분석은 **지역 → 종류 →
실행** 세 걸음이고 업종 칸을 아예 보지 않는다. `canRun`은
`region && kind && (!needsIndustry || industry)`라 필요한 최소 입력이 다 차야
[분석 실행]이 열린다.

실행 전에는 지도에 지점을 띄우지 않는다(`overlay.setMap(ran ? map : null)`) — 그래야
[분석 실행]이 뜻을 갖는다. 필지 지점은 **토지가치분석의 것이라** 상권분석에서는 띄우지
않는다. 상권분석은 필지를 고르는 분석이 아니므로, 안 쓰는 지점이 남아 있으면 누르라는
뜻으로 읽힌다. 대신 도보 도달권 세 겹이 원으로 올라간다(`kakao.maps.Circle`, 350·700·
1,100m) — 화면이 스스로 "원은 근사이고 실제 도달권은 가로망을 따라 찌그러진다"고
밝힌다.

### 상권분석도 같은 규칙으로 여섯 탭이다

지금 서비스는 상권분석 결과를 네 섹션(`입지 진단` / `업종 분석` / `시세·유동인구` /
`확장 분석`)으로 내는데, 「확장 분석」 한 칸에 도달권·잠식·시너지·추세가 다 들어가 있고
임대 타당성은 아예 다른 화면에 있다. 데모는 같은 재료를 **탭 하나가 질문 하나에 답하도록**
다시 묶었다(`TRADE_TABS`, `DEFAULT_TRADE_TAB = "t-site"`).

| 탭 | 컴포넌트 | 답하는 질문 |
| --- | --- | --- |
| 종합 | `TradeOverview` | 이 자리에서 이 업종을 하면 어떤가 |
| 입지진단 | `TradeSite` | 무엇이 좋고 무엇이 약한가 (6항목 + Space Syntax + 교통) |
| 수요·도달권 | `TradeDemand` | 손님이 어디서, 몇 시에 오는가 (도달권 표 + 24시간 막대 + 연령·요일) |
| 경쟁·잠식 | `TradeRival` | 누가 같은 손님을 나눠 갖는가 (동일 업종·잠식 %·인접 경쟁·시너지) |
| 매출·손익 | `TradeMoney` | 얼마를 벌어야 남는가 (추정매출·서울 대비·적정 임대료 밴드·손익분기) |
| 상권추세 | `TradeTrend` | 커지고 있는가 줄고 있는가 (8분기 꺾은선·거리 신호·닮은 상권) |

상권 쪽 예시 값은 **난수가 아니라 고정 표**다(`demoTrade.ts`의 `INDUSTRY` / `REGION`).
발표 중에 같은 업종을 두 번 눌러 숫자가 달라지면 안 되고, 손으로 적은 값이 난수보다
그럴듯하기 때문이다. 업종 여섯 개가 서로 다른 시간대 모양·객단가·정점 시각을 갖는다 —
**업종을 받는 이유가 화면에 보여야** 업종 단계가 뜻을 갖는다.

경쟁 점포에 **상호를 쓰지 않는다.** 지어낸 판정을 실재하는 가게에 붙이면 데모가 아니라
명예훼손이다. 거리와 성격만 쓴다(테스트가 이걸 지킨다).

### AI는 마지막 막이다 — 입구가 아니라 설명 창구

`ChatOverlay`가 소개 세 칸과 예시 대화 하나를 함께 낸다. 질문 둘 다 **결과를 이미 본
사람이 하는 질문**이다: "여기 카페 자리로 괜찮다고 했는데, 그럼 뭘 조심해야 해?"(상권),
"이 필지가 3년 뒤에도 오를 거라고 본 근거가 뭐야?"(토지가치).

답에는 도구 이름과 소요 시간이 함께 뜬다(`상권_점포밀도` · `도구 3회 · 11.2초`) — 실제
서비스의 도구 루프가 **5초 룰의 유일한 예외**라는 사실을 화면이 밝히기 위해서다. 답의
숫자는 앞 탭들이 보여 준 값과 같아야 하며, `tests/demoChat.test.ts`가 그것을 강제한다.
AI가 다른 숫자를 말하면 보는 사람은 둘 중 어느 쪽이 제품인지 알 수 없다.

## 뒤집는 결정

### 1. ⚠️ 사용자에게 잔차(Gap)를 내보낸다 — 확정 결정의 반대다

`SPEC_PARCEL_LAND_VALUE_UI.md`가 이렇게 적어 놨다:

> 헤도닉 잔차 점수를 **도입하지 않는다.** … 잔차는 "저평가"가 아니라 행정 산식
> 내부의 오차다. … 계수는 보고하되 **잔차는 사용자에게 내보내지 않는다.**

근거는 강동구 42,957필지 실측이다 — 잔차 상위 20개와 현재 갭 점수 상위 20개가
**하나도 겹치지 않았고**(Spearman 0.35), 어느 쪽이 옳은지 사용자가 판별할 수단이
없다. 그리고 R² 분해에서 용도지역(+0.25)과 도로접면(+0.21)이 설명력 대부분인데
**그 둘이 토지가격비준표 항목 자체**다(순환성).

새 Tab 「가치평가」의 `Gap = (모델 예측 − 실제)/실제 → 저평가 후보`는 **정확히 그
잔차**다. 뒤집으려면 ADR로 남긴다. → 미결 Q1

### 2. ⚠️ 필지 상세를 대화 밖으로 낸다

같은 문서:

> 대화와 지도 두 칸이다. **세 번째 칸(데이터 패널)을 두지 않는다.** 필지 상세는
> 대화 안의 카드로 나타나므로 같은 정보가 두 곳에 나오는 중복이 없다.

새 구조는 결과가 탭형 화면이고 AI가 후속 창구다. 이건 **제품 방향의 반전**이라
ADR을 남길 값이 있다. → 미결 Q6
