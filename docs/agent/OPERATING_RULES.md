# 자율 개발 운영 규칙 (2026-07-29 결정, 07-30 개정)

에이전트 러너가 사람 없이 개발·검사·개선을 이어간다. 아래는 **확정된 결정**이며 러너와
subagent 모두 따른다. 상태 파일 구조는 `docs/agent/README.md`.

현재 상태: 러너는 **꺼져 있다** (2026-08-01 기준). 다시 켜기 전에 이 문서를 읽는다.

## 배포 — 검증 통과분을 main에 바로 올린다

`main`에 push하면 그 즉시 라이브다. 러너는 **검증(pytest·typecheck·test·lint)을 통과한
변경만** 최신 main 위에 rebase해서 push한다. 경합으로 튕기면 다시 rebase해 재시도하고,
3회 실패하거나 rebase가 충돌하면 `auto/<작업id>` 브랜치로 물러난다 — 그 경우는 사람이
봐야 하고 STATUS/HANDOFF에 "사람 확인 필요"로 남는다.

2026-07-29에 `auto/*` 브랜치+PR로 바꿨다가 하루 만에 되돌렸다. **브랜치에 담아 두면
아무도 병합하지 않았다** — 하루에 101개가 쌓이고 그중 67개는 베이스가 100커밋 이상
뒤처져 같은 파일(`backend/app/routers/agent.py` 등)에서 충돌해 통째로 버렸다. 밤새
80건을 처리했는데 라이브 반영은 0건이었다.

브랜치로 바꾼 원래 이유 둘은 이렇게 갚는다:

1. "사람이 화면으로 확인한 게 0건" → 사람이 하루 한두 번 라이브를 눈으로 점검한다.
   자동 검증은 회귀를 막는 것이지 화면 확인을 대신하지 않는다.
2. "같은 main에서 충돌" → 상태 커밋을 `agent-state` 브랜치로 옮겨 main의 러너 커밋이
   하루 150개에서 실제 작업분만 남았다.

상태 파일(`docs/agent/`)은 `agent-state` 브랜치로 올린다 (2026-07-30 변경 — 처음엔
main에 올렸는데, Railway 서비스가 GitHub에 직접 연결돼 있어 main의 모든 커밋이 재빌드를
띄웠고, 매 사이클 상태 커밋이 자기 컨테이너와 라이브 백엔드를 10분마다 재시작시켰다).
러너는 부팅할 때 이 브랜치에서 상태를 되살리므로 기억을 잃지 않는다. 사람이 러너 상태를
보려면 `agent-state` 브랜치의 `docs/agent/`를 본다.

push 전 로컬 검증은 유일한 안전망이고 타협하지 않는다:

- 백엔드 `pytest -q` 통과 (DB 없이도 565/584가 돌아 러너가 검증할 수 있다)
- 프론트 `npm run typecheck && npm test && npm run lint` 통과
- 회귀 스크립트가 있으면 그것까지

**검증이 실패하면 push하지 않는다.** 실패를 `FAILURES.md`에 적고 다음 작업으로 넘어간다.
라이브를 깨는 것보다 작업 하나를 미루는 게 항상 싸다.

## 여전히 사람 승인이 필요한 것

막히면 **전체를 멈추지 말고** `BACKLOG.md`에 `blocked`로 적고 다른 작업을 계속한다.

- 운영 데이터 변경·삭제, DB migration의 운영 반영
- 유료 서비스 가입, 예산 한도를 넘는 API 사용, 결제·구매·계약
- 비밀키·권한·보안 정책 변경
- 외부 사용자에게 메시지 전송
- 기존 기능의 대규모 삭제

## 인증 — 구독 토큰을 쓴다

러너는 `CLAUDE_CODE_OAUTH_TOKEN`(`claude setup-token`으로 발급한 1년짜리 구독 토큰)으로
인증한다. **API 과금이 아니라 구독으로 청구된다.**

**추가 비용은 쓰지 않는다** (소유자 결정 2026-07-29). API 폴백은 꺼져 있고
(`auth.api_fallback=false`, `budget.daily_limit_usd=0`), 구독 한도에 걸리면 알림을 보내고
기다린다. 한도가 풀리면 알아서 재개한다.

토큰과 API 키는 다른 것이다 — 토큰은 이미 내고 있는 구독으로 인증하는 열쇠라 추가 비용이
없고, 돈이 나가는 건 `ANTHROPIC_API_KEY` 쪽뿐이다.

- `--bare`를 쓰면 이 토큰을 안 읽는다. 러너는 `--bare`를 쓰지 않는다.
- `ANTHROPIC_API_KEY`가 환경에 있으면 그쪽이 우선한다(우선순위 3 > 5). 폴백이 꺼져 있는
  동안 이 키를 환경에 두면 안 된다 — 두는 순간 과금된다.
- 소유자 PC에서 돌리면 토큰조차 필요 없다(이미 로그인돼 있다). 대신 PC를 켜 둬야 한다.
  Railway는 PC를 꺼도 돌지만 토큰 발급이 한 번 필요하다.

## 실행 제한

| 항목 | 값 |
| --- | --- |
| 최대 동시 agent | 3 (supervisor 1 + worker 2) |
| 위임 깊이 | 1 — worker는 다른 agent를 만들지 않는다 |
| agent당 실행시간 | 20분, 초과 시 kill + failed 기록 |
| retry | 2회, 이후 blocked |
| 연속 실패 | 3건이면 일시정지 + 알림 |

## 작업 소유권

같은 파일을 두 agent가 동시에 고치지 않는다. 작업마다 worktree를 따로 쓰고
`task-state.json`의 `files`에 소유 범위를 적는다. 범위 밖 파일은 건드리지 않는다.

## 상태는 파일이 정본이다

대화 기억에 의존하지 않는다. `docs/agent/` 아래 상태를 읽고 마지막 작업부터 재개한다.

  매시 34분 시작, 자동 승인. 예약 간격 최소가 1시간이라(15분은 거부됨) 한 실행 안에서 15분짜리
