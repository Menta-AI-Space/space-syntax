## 품질 기준 (타협하지 않는다)

- **화면에 적힌 것과 실제 계산된 것이 달라선 안 된다.** 2026-07-28 밤에 찾은
  결함 18건 중 12건이 이 유형이었다. 특히 "높을수록 나쁜 지표"(경쟁·포화·잠식)를
  좋은 쪽으로 그리거나 정렬하는 것 — 규칙은 `frontend-next/lib/metricDirection.ts`.
- **없는 값을 지어내지 않는다.** 하드코딩 상수를 분석 결과처럼 적지 않는다.
- **못 믿는 값으로 점수를 매기지 않는다.** 폴백이면 폴백이라고 화면에 적는다.
- 분석은 5초 안에 — 다만 이 룰은 재검토 대기 중이다(`docs/PERF_AREA_SEARCH.md`).

## 오너 지시 (2026-07-29 저녁) — 다음 우선순위

아래는 사람이 직접 정한 다음 작업 방향이다. 순서는 우선순위가 아니라 적은 순서.
각 항목이 여러 하위 작업이면 backlog에 나눠 담아도 된다.

1. **버그: 업종 세부 메뉴어가 "한식"으로 잘못 고정된다.**
   `backend/app/services/sbiz_upjong.py`의 `BUSINESS_TYPE_PRESETS["restaurant"]`가
   `inds_mcls_cd: I201`(한식)로 하드코딩돼 있어, `agent.py`의 키워드 폴백이
   "샐러드"처럼 한식이 아닌 음식점을 restaurant 프리셋에 매칭시키면 전부 "한식
   음식점업"으로 표시되고 동일업종 경쟁수까지 한식 기준으로 잘못 집계된다.
   정확한 소분류(SBIZ scls)로 보내거나, 프리셋에 없으면 "일반 음식점"처럼
   업종을 특정하지 않는 라벨로 폴백해야 한다. 화면 라벨과 경쟁 집계 기준이
   실제 업종과 어긋나면 안 된다(품질 기준 참고).

2. **새 분석 예시 문구를 아래 두 가지 실사용 의도로 교체.**
   `frontend-next/components/agent/AgentChat.tsx`의 `EXAMPLES`.
   - **[지역+업종] → 어느 골목이 좋은지 비교**: "신촌에서 카페 하려면 어떤
     골목이 좋은지 비교해줘" 같은 식. 특정 주소 하나를 찍어주면 안 된다 —
     그 주소가 공실이 아닐 수 있어 무의미하다(실제로 확인된 사례 있음). 대신
     아래 3번 골목 비교 기능으로 연결한다.
   - **[구체 주소+업종] → 이 자리 어때**: "역삼동 794-9 카페 자리 어때?"
     같은 식. 이건 지금 있는 site_score 흐름 그대로.

3. **[핵심 신규] 골목(도로 구간) 단위 비교 기능.**
   "신촌에서 카페 하려면 어떤 골목이 좋은지 비교해줘" 류 질문에 답하는 기능이
   지금 없다. 반경 내 여러 골목(segment)을 space syntax 지표(integration·choice)
   기준으로 후보로 뽑아, 각 골목의 유동인구·연령대 구성·매출 추정·경쟁을
   나란히 비교해 보여준다("이 골목은 유동인구 많고 20대가 많이 다님", "저
   골목은 매출 추정이 더 높음" 식). 결과는 각 골목을 지도에 표시하고, 표나
   그래프로 정리해서 사람이 한눈에 비교할 수 있게 한다(글로 길게 나열 금지).

4. **매출 데이터를 골목 단위로 세분화할 수 있는지 조사 후 반영.**
   지금 매출 벤치마크(`trdar_sales_local.py` 등)는 상권/동 단위. 서울시
   상권분석서비스가 "표준단위구역" 단위로 카드매출을 제공하는데(동보다
   세밀, data.seoul.go.kr OA-15572), 이게 골목(도로 구간)에 매핑 가능한지
   확인하고, 안 되면 상권/동 단위 매출을 space syntax 지표로 골목별 배분
   추정하는 방식을 검토한다. 3번 골목 비교 기능의 전제 조건.

5. **"새 분석"과 "입지 분석" 탭을 하나로 통합.**
   "새 분석"이라는 이름 자체가 사용자에게 뭘 하는 탭인지 안 와닿는다는 지적.
   하나의 "입지 분석" 화면으로 합쳐, 위쪽에 자연어(LLM) 질의창을 두고 아래쪽에
   지도를 배치한다. 지도에서도 직접 검색·클릭으로 분석을 시작할 수 있게 한다.

6. **결과를 인플로우(수익)/아웃플로우(비용) 두 축으로, 절대값 대신 상대치로.**
   - **인플로우**: 소득 수준·아파트 시세는 절대 숫자만 주지 말고 "서울 평균
     대비 +N%" 또는 "상위 N%"로 — 일반인은 절대값만 보면 높낮이 감을 못
     잡는다. 소비 여력 있는 인구 중 실제 타깃 고객층 비율(예: "전체 인구 중
     20대 여성이 N%")을 직관적으로 보여준다. 경쟁 점포 수도 함께.
   - **아웃플로우**: 창업 비용 지표(임대료·권리금·초기비용 등)를 국내외
     플랫폼(Placer.ai·GrowthFactor·오픈업·나이스비즈맵 등, 이전 세션에서
     1차 조사함) 사례를 참고해 보강. 인플로우·아웃플로우를 종합해 "여기가
     좋다/아니다" 결론까지 내는 게 목표.

7. **지도 색상 범례가 뭘 뜻하는지 쉬운 말로 표시.**
   `frontend-next/components/map/KakaoMap.tsx`의 `MapLegend`가 지금 색상이
   무엇을 의미하는지 사용자가 쉬운 말로 알 수 있게 나오는지 확인 — "이 골목
   색이 파란색이면 뭐가 좋다" 식으로.
